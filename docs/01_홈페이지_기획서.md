## 1. 프로젝트 개요

### 1.1 목적

JSTech의 임베디드 개발 용역 역량을 효과적으로 전달하고, 잠재 고객의 프로젝트 문의를 유도하는 전문 기업 홈페이지 구축.

### 1.2 핵심 목표

| 목표 | 측정 지표 |
|------|----------|
| 브랜드 신뢰도 구축 | 체류시간 3분 이상, 이탈률 40% 이하 |
| 프로젝트 문의 유도 | 월간 문의 10건 이상, 전환율 3% 이상 |
| 기술 전문성 어필 | 프로젝트 포트폴리오 페이지 평균 조회 500+/월 |
| 검색 유입 확대 | 키워드 30개 이상 상위 10위권 진입 |
| 제품 판매 (신규) | 월간 제품 판매 50건 이상, 장바구니 전환율 2% 이상 |
| 교육 유치 (신규) | 월간 수강 신청 20건 이상, 신규 과정 등록 5건/분기 |

### 1.3 타겟 오디언스

| 페르소나 | 특성 | 핵심 관심사 |
|----------|------|------------|
| **스타트업 대표/CTO** | 아이디어→제품화 단계, 예산 민감 | 빠른 프로토타입, 비용 효율, 기술 상담 |
| **중소기업 R&D 담당** | 기존 제품 개선/신규 라인 확대 | 양산 지원, 기술 문서, 안정성 |
| **대기업 PM/조달** | 협력사 발주, 공공과제 연계 | 인증(KC/EMC), 대규모 납품 이력, 보안 |
| **해외 바이어** | OEM/ODM 수요, 영문 정보 필요 | 다국어 지원, 글로벌 파트너십 |
| **입문·비전문가 (신규)** | 임베디드에 대한 이해가 없음, 막연히 제품화를 원함 | 쉬운 설명, 단계별 가이드, 어떤 도움이 필요한지 파악 |
| **제품 구매자 (신규)** | 기성 개발보드/모듈/제품 구매 희망 | 제품 사양, 가격, 구매 방법, 기술지원 |
| **교육 수강생 (신규)** | 임베디드/C/C++ 학습 희망 (학생, 재직자, 취준생) | 교육 과정, 커리큘럼, 수강료, 수료 후 진로 |

### 1.4 신규 비즈니스 영역 (v1.3 추가)

기존의 **임베디드 개발 용역**에 더해, 홈페이지를 통해 3가지 사업영역을 추가 확장한다.

| 사업영역 | 타겟 | 홈페이지 역할 |
|----------|------|--------------|
| **개발 용역** (기존) | 기업 | 프로젝트 문의, 포트폴리오, 견적 시뮬레이터 |
| **제품 판매** (신규) | 기업+개인 | 개발보드/모듈/번들 제품 쇼핑몰 기능 |
| **교육** (신규) | 개인+기업 | 온라인/오프라인 강좌, 커리큘럼, 수강 신청 |

### 1.5 핵심 메시지

```
아이디어 → 시제품 → 양산까지, JSTech가 함께합니다.
"기획부터 양산까지, 원스톱 임베디드 개발 파트너"
```

## 5. JSTech 차별화 전략

### 5.1 핵심 차별화 포인트 (Unique Selling Propositions)

#### 차별화 0: "11년+ 업력" — 검증된 전문성 (2015~2026)
- 2015년 설립 이후 11년간 축적된 임베디드 개발 노하우
- 경쟁사 대비 3~6년 앞선 업력으로 신뢰도 극대화
- "11년, 수백 개의 프로젝트, 한결같은 품질" — 히어로 핵심 메시지

#### 차별화 1: "개발비 투명성" — 업계 최초 온라인 견적 시뮬레이터
- 고객이 MCU 플랫폼, 통신 방식, 산업 분야를 선택하면 예상 견적 범위 표시
- "당신의 프로젝트 비용은 얼마일까요?" — 문의 전 확인 가능
- 경쟁사 대비 높은 접근성과 신뢰 구축

#### 차별화 2: "프로젝트 라이브 뷰" — 진행 중인 프로젝트 실시간 현황
- 현재 진행 중인 프로젝트의 단계(설계/개발/테스트)를 실시간으로 표시
- "지금 이 순간에도 프로젝트를 수행하고 있습니다" — 활발한 사업 증거
- 비트버스의 "시스템 상태: 정상 운영" 개념을 프로젝트 영역으로 확장

#### 차별화 3: " industy별 솔루션 허브" — 산업 도메인 중심 구성
- 의료기기 / 스마트팩토리 / 모빌리티 / IoT / 소비재 5개 허브
- 각 허브에서 관련 기술, 사례, 견적 가이드를 원스톱 제공
- j-iot의 "기술 중심" 구조를 "산업 중심"으로 재구성

#### 차별화 4: "비디오 기술 데모" — 말이 아닌 제품으로 증명

## 8. 입문·비전문가 가이드 (신규)

### 8.1 목적

임베디드에 대한 사전 지식이 없는 **비전문가·입문자**가 이 방문자도 쉽게 이해하고, "무엇을 할 수 있고, 무엇을 물어야 하는지"를 알도록 돕는 진입장벽 완화 섹션.

**등장 배경**: 경쟁사 홈페이지는 대부분 전문가용 기술 용어로 가득 차 있어, "아이디어만 있는 고객"이나 "개발을 처음 배우려는 사람"에게 진입장벽이 높음. JSTech는 비전문가에게도 친절한 가이드로 접근성을 차별화한다.

### 8.2 타겟

| 타겟 | 상황 | 니즈 |
|------|------|------|
| **아이디어 보유자** | 제품 아이디어만 있고 기술 지식 없음 | "어떻게 시작해야 할까?" 길잡이 |
| **예비 창업자** | 프로토타입을 만들고 싶음 | 개발 용역/교육/제품 구매 중 어떤 게 맞는지 |
| **학생/취준생** | 임베디드 개발자 지망 | C/C++ 학습, 교육 과정 안내 |
| **일반 소비자** | IoT/스마트 제품에 관심 | 잘 이해하는 콘텐츠로 신뢰 형성 |

### 8.3 페이지별 상세

#### 8.3.1 임베디드란 무엇인가 (/learn/what-is-embedded)

- **쉬운 언어**: 전문 용어를 일상어로 풀어 설명
- **시각적 자료**: 인포그래픽, 다이어그램, 예시 사진
- **내용 구성**:
  ```
  1. 임베디드 시스템이란? (일상 예: 세탁기, 냉장고, 자동차, 스마트폰)
  2. 펌웨어 vs 하드웨어 vs 소프트웨어 (쉽게)
  3. MCU란? (작지만 똑똑한 컴퓨터 한 개의 칩)
  4. 임베디드 개발이 필요한 순간 (예시 상황)
  5. JSTech가 어떻게 도와줄 수 있는지 (용역/제품/교육 연결)
  ```

#### 8.3.2 C/C++ 첫걸음 (/learn/cpp-basics)

- 초보자를 위한 C/C++ 입문 콘텐츠 (무료 제공)
- 코드 예시 + 실행 결과 화면
- **교육 과정으로의 자연스러운 유도** (CTA: "심화 과정 등록")

#### 8.3.3 나의 아이디어 제품화하기 (/learn/productize-idea)

- **비전문가용 의사결정 트리**: 아이디어 → 무엇을 해야 하나?
  ```
  내 상황을 선택하세요
  ├── 아이디어만 있다 → [무료 상담 신청] (개발 용역)
  ├── 프로토타입이 필요 → [견적 시뮬레이터] + [프로젝트 문의]
  ├── 완성된 부품이 필요 → [제품 스토어]
  └── 직접 배워서 만들고 싶다 → [교육 과정]
  ```
- 개발 비용/기간에 대한 현실적인 안내 (비전문가 눈높이)
- 실패를 줄이는 체크리스트

#### 8.3.4 자주 묻는 질문 (초보자용 FAQ) (/learn/faq)

비전문가가 가장 흔히 하는 질문 목록:
- "의뢰하는데 기술 지식이 없어도 되나요?" → 네, 가능합니다.
- "비용은 얼마나 드나요?" → 견적 시뮬레이터 연결
- "개발 기간은 얼마나 걸리나요?" → 단계별 안내
- "직접 배우고 싶은데 어디서 시작하나요?" → 교육 과정 안내

#### 8.3.5 용어 사전 (/learn/glossary)

전문 용어를 알파벳/주제별로 쉽게 정리한 미니 사전 (검색 기능 포함).

### 8.4 진입장벽 완화 설계 원칙

1. **9세도 이해하는 문장**: 한 문장에 전문 용어 1개 이하
2. **항상 "다음 단계" CTA**: 각 페이지 끝에 용역/제품/교육 중 적절한 행동 유도
3. **비전문가 경로 vs 전문가 경로 분리**: 전문가는 바로 "사업영역/견적"으로, 비전문가는 "가이드"로
4. **무료 콘텐츠 제공**: 기초 가이드는 무료 → 신뢰 + 유입 + 교육 유치

## 9. 제품 판매 페이지 (신규)

### 9.1 목적

JSTech가 보유/제작한 **기성 제품(개발보드, 모듈, 번들, 센서 키트)**을 온라인에서 직접 판매하는 쇼핑몰 기능. 개발 용역 수요를 자사 제품 매출로 다각화.

### 9.2 판매 대상 제품 카테고리

| 카테고리 | 예시 | 타겟 |
|----------|------|------|
| **개발보드** | STM32 기반 커스텀 보드, ESP32 보드 | 개발자, 기업 R&D |
| **통신 모듈** | LoRa, BLE, WiFi 모듈 | IoT 프로젝트 |
| **번들 키트** | 센서+보드+간단한 시작 가이드 | 입문자, 교육 |
| **완제품** | 모니터링 게이트웨이, 측정 장치 | 산업 고객 |
| **부자재** | 케이블, 젠더, 전원 어댑터 | 개인 |

### 9.3 필요한 기능

```
[제품 목록] → [상품 상세] → [장바구니] → [결제] → [주문 완료] → [마이페이지/주문내역]
     └─────── 필터(카테고리/가격/재고) ────────┘

- 검색
- 재고 관리 / 품절 표시
- 장바구니 (수량 변경, 삭제)
- 결제 (카드/계좌이체/무통장, PG 연동)
- 배송정보 (배송회사 연동/추적)
- 리뷰 / 평점
- 상품 Q&A (기술 문의)
- 주문내역 / 주문 상태 조회
- 쿠폰/할인 (선택)
```

### 9.4 결제/주문 프로세스

| 단계 | 화면 | 설명 |
|------|------|------|
| 1 | 상품 선택 | 카테고리/검색으로 제품 탐색 |
| 2 | 수량 선택 | 수량 + 옵션(색상/버전) |
| 3 | 장바구니 | 담긴 상품 확인, 수량 변경 |
| 4 | 결제 | 카드/무통장, 배송지/주문자 입력 |
| 5 | 주문 완료 | 주문번호, 예상 배송일 |
| 6 | 배송 추적 | 배송 상태 확인 |

### 9.5 상품 상세 페이지 구성

```
1. 제품 이미지 갤러리 (제품 사진 + 사용 사진)
2. 제품명 + 간단한 소개 (비전문가도 이해)
3. 가격 / 재고 / 수량 선택 + [장바구니] [바로구매]
4. 상세 사양 (표 + PDF 다운로드)
5. 기술 스펙 (핀맵, 전압, 통신 등) — 전문가용 탭
6. 사용 방법 / 시작 가이드 (비전문가용 탭)
7. 리뷰 / 평점
8. Q&A / 기술 문의
9. 관련 제품 추천
10. [교육 과정 연결] — 제품 구매자 → 교육 안내
```

### 9.6 제품 판매의 기대 효과

- 자사 제품의 인지도 향상 및 직접 매출
- 개발 용역 → 제품 → 교육의 **선순환 생태계** 구축
- 입문자가 저렴한 키트로 시작 → 유료 교육/용역으로 승급
- 오픈소스/참고자료 제공으로 개발자 커뮤니티 형성

## 10. 교육 페이지 (신규)

### 10.1 목적

임베디드/C/C++/IoT 교육 과정을 온라인·오프라인으로 제공하여, JSTech의 11년 노하우를 전수하고 인재를 양성한다. 교육은 **수익원 + 인재 발굴 + 기술 대중화**의 3중 역할.

### 10.2 교육 과정 카테고리

| 유형 | 대상 | 형태 | 예시 과정 |
|------|------|------|----------|
| **입문 과정** | 비전문가, 학생 | 온라인 | "C/C++ 첫걸음", "임베디드 기초" |
| **실무 과정** | 재직자, 취준생 | 오프라인 | "STM32 펌웨어 실무", "Qt GUI 개발" |
| **심화 과정** | 경력 개발자 | 오프라인/온라인 | "IoT 통신 프로토콜 실전", "FreeRTOS/RTOs" |
| **기업 맞춤 교육** | 기업/단체 | 방문/위탁 | "기업 재직자 임베디드 부트캠프" |
| **키트 번들 과정** | 입문자 | 온라인+키트 | "하드웨어 키트로 배우는 IoT" |

### 10.3 과정 상세 페이지 구성

```
1. 과정명 + 한 줄 소개 (이수 후 할 수 있는 것)
2. 과정 개요: 난이도, 기간, 수강료, 수강 대상
3. 커리큘럼 (주차별 상세)
4. 강사 소개 (경력, 대표 프로젝트)
5. 수강료 / 환급 (국비지원 여부, 할인)
6. 일정 (캘린더 연동)
7. 수강 신청 폼
8. 수강 후기
9. [제품 키트 연결] — 실습용 키트 구매 유도
10. FAQ
```

### 10.4 수강 신청 및 결제 흐름

```
수강 신청 → 결제(카드/무통장) → 이메일/문자 확인 → 수강 확정
                                                      ↓
                              온라인강의: 학습 플랫폼 접속 권한 부여
                              오프라인강의: 장소/시간 안내
```

### 10.5 온라인 학습 플랫폼 요건 (초기 단순화)

- **초기 MVP**: 기존 LMS(학습관리시스템) 또는 유튜브 프리미엄/웹호스팅 강의 업로드로 시작
- **중기 확장**: 자체 학습 대시보드, 수강생 진도 관리, 시험/인증
- **수료 인증서 발급**: JSTech 공인 수료증 (취업/이직 활용)

### 10.6 기업 교육 (B2B) 제안

- 기업 재직자 대상 맞춤 커리큘럼 설계 (위탁교육)
- 국비지원 연계 (HRD-Net) 가능 여부 검토
- 정부 지원사업(중소기업 기술지도 등) 활용 검토

### 10.7 교육의 기대 효과

- 교육 수익 창출 (신규 수익원)
- 우수 수강생을 **JSTech 채용/협력**으로 연결 (인재 발굴)
- 글로벌 임베디드 개발자 생태계 조성
- 기술 대중화로 JSTech 브랜드 인지도 향상

## 11. 디자인 방향성

> **v1.4 핵심 원칙**: "모바일에서 잘 보이는 반응형 웹" + "복잡하지 않고 심플한 디자인"
> 간결하고 직관적인 UI로, 비전문가도 부담 없이 이용할 수 있게 한다.

### 11.1 비주얼 아이덴티티

| 요소 | 방향 | 비고 |
|------|------|------|
| **.primary 컬러** | #1A73E8 (텍니컬 블루) | 신뢰, 전문성 |
| **.secondary** | #34A853 (그린) | 성장, 혁신 |
| **accent** | #FBBC04 (앰버) | 주목, 에너지 (최소한으로) |
| **background** | #FFFFFF / #F8F9FA | 깔끔, 여백 |
| **dark mode** | #121212 / #1E1E1E | 개발자 타겟, 기술적 느낌 |
| **타이포** | Pretendard (한글) + Inter (영문) | 깔끔한 산세리프 |
| **아이콘** | 기술 관련 아이콘 (MCU, chip, antenna) | Lucide or Phosphor |
| **이미지** | 실제 프로젝트 사진 위주 | 스톡 이미지 최소화 |

### 11.2 단순·심플 디자인 원칙 (v1.4 추가)

복잡함을 버리고, 필요한 것만 남기는 **미니멀리즘** 지향.

1. **정보의 최소화**: 한 화면에 하나의 핵심 메시지 (산만함 제거)
2. **5초 이해**: 히어로에서 "무엇을 하는 회사인지" 즉시 파악
3. **큰 여백 (White Space)**: 콘텐츠 주위에 충분한 여백으로 시선 집중
4. **색상 절제**: 주 색상 1~2개 + 무채색 중심 (과한 색 사용 금지)
5. **한 가지 글꼴 계열**: 타이포 계층(제목/본문/캡션)만 명확히 구분
6. **간결한 문장**: 전문 용어 줄이고 짧고 명확한 카피
7. **과한 애니메이션 제거**: 필요한 곳에만 아주 가볍게 (속도 인식 개선)
8. **모바일 우선 (Mobile-First)**: 작은 화면 기준으로 먼저 설계

### 11.3 반응형 웹 (Responsive Web) 설계 (v1.4 추가)

**핵심 원칙**: 데스크톱/태블릿/모바일에서 모두 자연스럽게 보이는 **반응형 웹**.

#### 반응형 설계 원칙

| 원칙 | 설명 |
|------|------|
| **모바일 퍼스트** | 모바일(360px)부터 설계하고, 화면이 커질수록 레이아웃 확장 (mobile-first, desktop-up) |
| **유동 그리드** | 고정 픽셀 대신 % / fr 단위 가변 레이아웃 |
| **유연한 이미지** | 이미지 최대 너비 100%, 자동 크기 조절 (max-width: 100%) |
| **미디어 쿼리** | Tailwind의 반응형 유틸리티 (sm/md/lg/xl)로 화면별 스타일 분기 |
| **터치 친화적** | 버튼/링크 크기 최소 44x44px, 손가락 터치 최적화 |
| **모바일 내비게이션** | 햄버거 메뉴, 하단 고정 CTA 등 모바일 UX 패턴 |

#### 브레이크포인트 (화면 분기)

| 크기 | 대상 | 레이아웃 |
|------|------|----------|
| ~640px (sm) | 스마트폰 | 단일 컬럼, 햄버거 메뉴, 하단 CTA |
| 641~1024px (md/lg) | 태블릿 | 2컬럼, 접힌 내비게이션 |
| 1025px+ (xl) | 데스크톱 | 다중 컬럼, 전체 내비게이션 |

#### 모바일 전용 고려사항

- **하단 고정 CTA 바**: 모바일에서 "문의하기/전화걸기" 버튼을 항상 노출
- **탭 크기 고려**: 클릭 영역을 충분히 크게
- **스크롤 최적화**: 모바일에서 과도한 섹션 피하기
- **로딩 성능**: 모바일 네트워크 기준 이미지 경량화 (WebP), LCP 2.5s 이하
- **글자 크기**: 본문 최소 16px (iOS 기본 확대 방지)
- **세로 최적화**: 세로 스크롤 중심, 가로 스크롤/줌 방지

#### 테스트 방법

- **기기별 확인**: 실제 스마트폰/태블릿/데스크톱에서 QA
- **브라우저 개발자 도구**: Chrome DevTools 기기 모드에서 다양한 화면 크기 시뮬레이션
- **반응형 테스트 도구**: Responsive Viewer, BrowserStack (선택)
- **실사용 점검**: 모바일에서 문의/구매/수강 신청 흐름이 매끄러운지 확인

### 11.4 인터랙션 패턴

- **스크롤 애니메이션**: fade-in, slide-up (subtle하게)
- **호버 효과**: 카드 리프트, 이미지 줌
- **技术 태그**: 컬러 뱃지로 기술 스택 시각화
- **카운터 애니메이션**: "11년+ 경력", "수백 개 프로젝트", "4개 MCU 플랫폼" 등 수치 강조
- **파티클/회로 배경**: 히어로 섹션에 서브𝒕𝒍한 기술적 요소

## 13. 홈페이지 배포 안내 (입문자·비전문가 기준) (신규)

> 홈페이지를 "만든 후 인터넷에 공개하는 방법"을, 기술 지식이 없는 분도 따라 할 수 있도록 쉽게 정리.

### 13.1 핵심 개념 이해

웹사이트가 인터넷에 보이려면 3가지가 필요하다.

```
① 코드(홈페이지 파일)  ─┐
② 도메인(주소, 예: jstech.com) ──→ ③ 호스팅/서버에 올려 공개
③ 호스팅(파일을 저장하는 공간)  ─┘
```

**비유 (이해를 돕기 위해)**:
- 홈페이지 파일 = 가게의 상품(물건)
- 호스팅(Vercel 등 배포 플랫폼) = 가게의 점포(진열 공간)
- 도메인 = 가게의 간판 주소 (사람들이 찾아가는 주소)

### 13.2 배포 방법 비교 (입문자 관점)

| 방법 | 난이도 | 비용 | 비고 |
|------|--------|------|------|
| **① Vercel / Netlify 배포 (추천)** | ★☆☆☆☆ 아주 쉬움 | 무료~ | GitHub 계정만 있으면 즉시 배포, 자동 업데이트, 무료 SSL(https) |
| **② 클라우드 서버 직접 운영** | ★★★☆☆ 보통 | 유료 | AWS/Google Cloud/NHN 등, 서버 설정/유지보수 필요 |
| **③ 웹호스팅 (카페24 등)** | ★★☆☆☆ 쉬움 | 유료(월 수천원) | 국내 호스팅, 관리 용이, 도메인 구매 가능 |
| **④ HTML파일 직접 업로드 (FTP)** | ★★☆☆☆ 쉬움 | 유료(호스팅) + 도메인 | 정적 사이트에만 적합 |

**입문자 권장**: **Vercel + GitHub** 조합이 가장 간단하고 무료이며, 수정하면 자동 배포된다.

### 13.3 추천 배포 방법: Vercel + GitHub (단계별 가이드)

#### 준비물
- GitHub 계정 (무료 가입)
- 홈페이지 소스 코드 (이 프로젝트에서 개발할 Next.js 홈페이지)

#### Step 1: GitHub에 코드 올리기

```
1. github.com 접속 → 로그인/회원가입
2. [New repository] 클릭 → 저장소(repo) 이름 설정 (예: jstech-home)
3. 로컬(내 컴퓨터)에서 생성한 홈페이지 폴더를 업로드
   - git 명령어 사용: git remote add origin <내 저장소 주소>
   - 또는 GitHub 웹에서 코드 파일 직접 업로드 가능
4. 코드가 GitHub에 올라가면 준비 완료
```

#### Step 2: Vercel에 연결하기

```
1. vercel.com 접속 → GitHub 계정으로 로그인
2. [Add New Project] 클릭
3. GitHub 저장소(JSTech_Home) 선택
4. 다음과 같이 설정 (Next.js 자동 인식)
   - Framework: Next.js (자동 선택됨)
   - Build Command / Output 등은 기본값 유지
5. [Deploy] 클릭
6. 배포 완료 → https://jstech-home.vercel.app 같은 주소 제공
```

#### Step 3: 도메인 연결 (원하는 주소 만들기)

> 무료로 먼저 시작해도 되지만, 회사 홈페이지는 가독성 좋은 도메인이 필요.

```
1. 도메인 구매: 가비아 / 호스팅케이알 / GoDaddy 등 (연 1만~2만원대)
   - 예: jstech.com, jstech.co.kr
2. Vercel 프로젝트 → Settings → Domains
3. 구매한 도메인 입력 → [Add]
4. 도메인 업체에서 DNS 설정을 Vercel 서버로 연결
   - Vercel이 안내하는대로 레코드(A/CNAME) 추가
5. 보통 수시간~24시간 후 도메인으로 접속 가능
```

> 실제 배포 시 Vercel 안내 화면을 따라가면 순서대로 진행된다. 어렵게 느껴지면 **Step 2까지만으로도 무료 주소(vercel.app)로 공개 가능**하다.

#### Step 4: 수정·업데이트 (자동 배포)

```
1. 코드를 수정
2. git push (GitHub에 올림)
3. Vercel이 자동 감지 → 자동 재배포 (수 초~수 분)
4. 인터넷에 즉시 반영 완료
```

> 매번 배포 명령을 실행할 필요 없다. GitHub에 올리기만 하면 자동 배포된다.

### 13.4 배포 체크리스트 (비전문가용)

- [ ] 로컬에서 정상 작동 확인
- [ ] 모바일(스마트폰)에서 정상 표시 확인 (반응형)
- [ ] https 적용 확인 (Vercel 기본 제공)
- [ ] 도메인 연결 후 www vs 비-www 리다이렉트 설정 확인
- [ ] 문의 폼 / 구매 / 수강 신청이 실제로 동작하는지 테스트
- [ ] 구글 검색 노출: Google Search Console에 사이트 등록
- [ ] 페이지 속도 측정: Google PageSpeed Insights로 최적화 여부 확인

### 13.5 배포 후 유지보수

| 항목 | 설명 |
|------|------|
| **백업** | GitHub에 소스가 있으므로 코드 백업 자동 유지 |
| **보안** | Vercel이 SSL(https) 및 보안 기본 제공 |
| **모니터링** | Vercel Analytics / Google Analytics로 방문자 확인 |
| **업데이트** | 콘텐츠 수정 → git push → 자동 반영 |
| **도메인 갱신** | 도메인 만료 전(연 단위) 갱신 알림 설정 |

## 14. 개발 로드맵

### 14.1 3-Phase Approach

```
Phase 1 (5주): MVP — 핵심 페이지
  ├── 홈
  ├── 회사소개
  ├── 사업영역 (통합 페이지)
  ├── 프로젝트 (목록 + 3건 상세)
  ├── 입문·비전문가 가이드 (/learn) 기본 3페이지
  ├── 문의
  └── 기본 SEO 설정

Phase 2 (4주): 확장 — 차별화 + 신규 사업
  ├── 견적 시뮬레이터
  ├── 기술 블로그 (MDX)
  ├── 제품 스토어 MVP (목록/상세/장바구니/결제)
  ├── 교육 과정 목록 + 상세 (수강 신청 폼)
  ├── 자료실
  └── 영문 버전

Phase 3 (3주): 고도화 — 최적화 + 운영
  ├── 다크모드
  ├── 쇼핑몰 고도화 (재고/주문내역/리뷰)
  ├── 온라인 학습 대시보드 (진도/수료증)
  ├── 성능 최적화 (Core Web Vitals)
  ├── A/B 테스트
  ├── Analytics 대시보드
  └── 모바일 최적화
```

### 14.2 마일스톤

| 주차 | 산출물 | 상태 |
|------|--------|------|
| W1-2 | 디자인 시안 (Figma) + 기술 스택 세팅 | ⬜ |
| W3-5 | Phase 1 개발 완료 (홈/소개/서비스/프로젝트/learn/문의) + QA | ⬜ |
| W6-7 | Phase 2 개발 완료 (견적/블로그/스토어/교육) + 콘텐츠 입력 | ⬜ |
| W8-10 | Phase 3 개발 완료 (쇼핑몰 고도화/학습 대시보드/최적화) + 런칭 | ⬜ |

## 15. 부록: B2B 홈페이지 베스트 프랙티스 (2026)

### 15.1 5초 테스트

> 방문자가 히어로 섹션을 보고 "이 회사가 뭘 하는지" 5초 안에 이해할 수 있는가?

**체크리스트**:
- [ ] 히어로 헤드라인이 서비스를 명확히 설명하는가?
- [ ] 부제목이 타겟 고객을 명시하는가?
- [ ] CTA 버튼이 눈에 띄는가?
- [ ] 첫 화면에 신뢰 요소(수치/로고)가 있는가?

### 15.2 전환 최적화

- **CTA 2~3회 반복**: 히어로, 중간, 하단
- **구체적 CTA**: "기술 상담 신청" > "문의하기"
- **저마찰 접근**: "무료", "부담 없이", "5분 상담"
- **다중 경로**: 폼 / 전화 / 이메일 / 채팅 / 캘린더

### 15.3 SEO 체크리스트

- [ ] 각 페이지 메타 타이틀/설정
- [ ] Open Graph 이미지 설정
- [ ] Schema.org Organization 마크업
- [ ] sitemap.xml 생성
- [ ] robots.txt 설정
- [ ] Core Web Vitals 최적화 (LCP < 2.5s, CLS < 0.1)
- [ ] 모바일 퍼스트 반응형

### 15.4 접근성

- [ ] WCAG 2.1 AA 컬러 대비 (4.5:1)
- [ ] 키보드 내비게이션 지원
- [ ] 이미지 alt 텍스트
- [ ] 시맨틱 HTML 구조
- [ ] 다크모드 지원
